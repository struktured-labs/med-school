# Med School: music and SFX (FamiStudio 4.5.3, 2A03 only, NTSC, no DPCM)

All music is original; nothing quotes another game's music. Everything here is generated by `gen_songs.py`.

## Files
- `gen_songs.py`: the source of truth. It writes the two FamiStudio text projects below.
- `med_school.txt`: the music project in FamiStudio text format (8 songs). FamiStudio can open or import it.
- `med_school_sfx.txt`: the SFX project (7 effects).
- `export/med_school_music.s`: music data for ca65 (label `music_data_med_school`, 4868 bytes).
- `export/med_school_music_songlist.inc`: song ID constants.
- `export/med_school_sfx.s`: SFX data (label `sounds`, NTSC, about 490 bytes).
- `engine/famistudio_ca65.s`, `engine/NoteTables/*.bin`: the stock FamiStudio 4.5.3 engine, unmodified.
- `engine/famistudio_cfg.inc`: the config (see below).
- `engine/med_school_audio.s`: the module to assemble. It includes the config, the engine and both data files.
- `test/`: an NROM harness (`stub.s`, `nrom.cfg`, `stub.nes`, `stub.map`). It is not game code.
- `previews/*.wav|*.mp3`: the rendered previews. Loops are rendered twice (Level Select three times).

Rebuild: `python3 gen_songs.py`, then run the FamiStudio CLI headless (DISPLAY/WAYLAND_DISPLAY unset):
  dotnet ~/opt/famistudio/FamiStudio.dll med_school.txt famistudio-asm-export export/med_school_music.s -famistudio-asm-format:ca65 -famistudio-asm-generate-list
  python3 fastvar.py export/med_school_music.s   # appends songs 8, 9
  dotnet ~/opt/famistudio/FamiStudio.dll med_school_sfx.txt famistudio-asm-sfx-export export/med_school_sfx.s -famistudio-asm-format:ca65 -famistudio-asm-sfx-mode:ntsc -famistudio-asm-sfx-generate-list

## IDs
Songs: 0 Rounds, 1 Code Blue, 2 Scrubs, 3 Title Fanfare, 4 Stage Clear, 5 Game Over, 6 Level Select, 7 Vitals,
       8 Scrubs Stat, 9 Vitals Rx (8/9: header-only fast variants of 2/7, same data, double frame every 5th frame).
SFX:   0 Rotate, 1 Land, 2 Clear, 3 Virus Clear, 4 Move (noise tick), 5 Combo P1, 6 Combo P2.
Jingles 3, 4 and 5 end on an empty bar that loops on itself, so they play once and then go silent. They never stop on their own. Call famistudio_music_stop or start the next song when you're done with them.

## Build integration
`ca65 engine/med_school_audio.s -o audio.o` (run it from engine/ so the includes resolve), then link audio.o.
Config (`famistudio_cfg.inc`): FAMISTUDIO_CFG_EXTERNAL=1, segments ZEROPAGE / BSS / CODE (via the
FAMISTUDIO_CA65_*_SEGMENT .defines), NTSC_SUPPORT=1, SFX_SUPPORT=1, SFX_STREAMS=2, DPCM_SUPPORT=0,
SMOOTH_VIBRATO=1. The data needs no FAMISTUDIO_USE_* features. Song and SFX data are placed in "RODATA".
Change the .defines and the `.segment` line if your linker config uses other names.
Measured in the test link: ZEROPAGE about 8 bytes, BSS 168 bytes, engine code about 1.95 KB, data 5357 bytes in RODATA.
No DPCM. Exported symbols: famistudio_init, famistudio_update, famistudio_music_play, famistudio_music_stop,
famistudio_music_pause, famistudio_sfx_init, famistudio_sfx_play, music_data_med_school, sounds (and _sounds).
The engine reads its data with plain pointers, so the data must sit in fixed PRG (no music bank switching).

## Calls
At boot:
  ldx #<music_data_med_school / ldy #>music_data_med_school / lda #1 (NTSC) / jsr famistudio_init
  ldx #<sounds / ldy #>sounds / jsr famistudio_sfx_init
Once per frame: jsr famistudio_update, from the NMI or from the main loop after the NMI. Save A, X and Y if you call it from the NMI. Call it exactly once per frame.
Play a song:  lda #song_id / jsr famistudio_music_play  (the song restarts at bar 1)
Stop:         jsr famistudio_music_stop      Pause: lda #1 / jsr famistudio_music_pause  (lda #0 resumes)
SFX:          lda #sfx_id / ldx #FAMISTUDIO_SFX_CH0 (or FAMISTUDIO_SFX_CH1) / jsr famistudio_sfx_play
  Suggested: rotate and land on CH0, clear and virus clear on CH1. SFX temporarily take over the music channels they use.

## Tempo and bar math (NTSC frames)
Every song is laid out as 1 pattern = 1 bar = 16 rows.
- Rounds: 6 frames/row with a hand-placed swing, so a bar is 96 frames (150 BPM). 24 bars = 2304 frames. Bars 0-15 are the loop, 16-23 the D minor bridge, then it repeats.
- Code Blue: 5 frames/row, so a bar is 80 frames (180 BPM). 24 bars with exactly the same layout as Rounds, transposed +2 semitones (G major, E minor bridge).
- Night Shift: 8 frames/row, so a bar is 128 frames (112.5 BPM). 24-bar loop.
- Level Select: 96 frames/bar, 4-bar loop.

## Switching Rounds to Code Blue (and back)
The stock engine can't seek inside a song, so play always starts at bar 1. Do it like this:
1. When you call music_play(Rounds), set a 16-bit frame counter to 0 and increment it each frame next to famistudio_update.
2. When danger begins, set a pending flag. On the frame where (counter mod 96) == 0, which is a Rounds bar boundary, call
   music_play(song_code_blue) and reset the counter. For a smoother musical seam, wait for (counter mod 384) == 0, which is a 4-bar phrase boundary.
   Every 4-bar group starts a phrase, and Code Blue's bar 1 is the hook.
3. To go back, do the same with mod 80 (or mod 320 for a phrase) and music_play(song_rounds).
Resuming at the same pattern position is not possible with the unmodified engine. The bar structures do match, so if the
engine ever gains a seek, bar N of Rounds maps to bar N of Code Blue.
